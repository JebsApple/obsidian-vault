## 🥩 Grilling (preguntas que resolver antes de empezar)

1. **¿Forzar `scrollTop = 0` en cada evento scroll no es caro?** El evento `scroll` se dispara a 60fps (cada 16ms). Forzar `scrollTop` en cada frame puede causar jank en el canvas (que también necesita renderizarse). Considerar alternativas:

2. **Alternativa más eficiente**: En vez de escuchar scroll, poner `overflow: hidden` en `<body>` cuando el modal se abre, y restaurar `overflow` cuando se cierra. Esto:
   - NO requiere escuchar eventos de scroll
   - NO causa reflows constantes
   - Es más predecible
   
   ```typescript
   useEffect(() => {
     const prevOverflow = document.body.style.overflow
     document.body.style.overflow = 'hidden'
     return () => { document.body.style.overflow = prevOverflow }
   }, [])
   ```
   
   ¿Funciona para este caso? Sí si el scroll que queremos evitar es el del body/document. Si no, usar la versión con event listener.

## Objetivo
Prevenir que el scroll del canvas afecte la posición del modal de Stitch cuando está abierto.

## Archivo a modificar

### `src/components/StitchModal.tsx`

**Opción A (recomendada)**: `overflow: hidden` en body — más eficiente:
```typescript
useEffect(() => {
  const prev = document.body.style.overflow
  const prevHtml = document.documentElement.style.overflow
  document.body.style.overflow = 'hidden'
  document.documentElement.style.overflow = 'hidden'
  return () => {
    document.body.style.overflow = prev
    document.documentElement.style.overflow = prevHtml
  }
}, [])
```

**Opción B**: Event listener en fase capture (solo si la opción A no funciona):
```typescript
useEffect(() => {
  const handler = () => {
    document.documentElement.scrollTop = 0
    document.body.scrollTop = 0
  }
  document.addEventListener('scroll', handler, { capture: true })
  return () => document.removeEventListener('scroll', handler, { capture: true })
}, [])
```
